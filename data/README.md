# `data/` — input artifacts and generated CSV/JSON

```
data/
├── lumo_damping_frequencies.json       LUMO per-recording frequencies + ζ
├── lumo_frequencies.json               hand-curated reference (paper Table 2 + local medians)
├── lumo_sds_expected.json              pinned reference for the three SDS scores
├── lumo_damping_ratio.json             LUMO per-recording ζ (damping ratio) cache
├── lumo_tower_coherence_states.json    LUMO whole-tower coherence (gamma^2) cache
├── lumo_tower_monthly_amp_phase.json   LUMO intra-dwell amplitude/phase cache
├── wind_response_shm.json              SHM wind-response suppression curves (DAM3/DAM6 only)
├── audit.csv / audit.json              the burst-cache audit sweep's own output
├── espoo_channels.csv / lumo_channels.csv   the two per-record channel CSVs
└── fig_espoo_channels.json / fig_lumo_channels.json /
    fig_burst_cache_audit.json / lumo_damping_gamma2_modulation.json
                                       the four ../figures/ scripts' .json artifacts
```

* `espoo_mast_observability.json` and `lumo_tower_monthly_timeseries.json` used
  to live here too; both were removed once `espoo_channels.csv` /
  `lumo_channels.csv` became the figures' only input and no script read either
  JSON directly any more (see `../code/figures_data_csv.py`'s docstring for the
  flattening they fed). `lumo_tower_monthly_timeseries.json`'s own top-level
  aggregates (`displacement_stack`, `monthly_summary`) were Rust-generated and
  are not reconstructable from this repository; its per-record fields, however,
  already survive in `lumo_channels.csv`.
* `lumo_damping_frequencies.json` — written by `../code/lumo_damping_frequencies.py`
  from the raw Uni-Hannover `.mat` recordings; per-state medians and all 30
  per-recording `f_peak_hz`/`zeta` rows.
* `lumo_frequencies.json` — hand-curated, not generated: the paper's Table 2 as
  transcribed, the local medians and the mode mapping; consulted only by
  `lumo_damping_frequencies.py --verify`.
* `lumo_sds_expected.json` — hand-curated, not generated: a pinned transcription
  of the three SDS scores; consulted only by `lumo_sds.py --verify`, never on
  the compute path.
* `lumo_damping_ratio.json`, `lumo_tower_coherence_states.json`,
  `lumo_tower_monthly_amp_phase.json`, `wind_response_shm.json` — read-only
  caches copied in from the sibling LUMO damage-state analyses
  (`lumo_dam3_analysis/`, `lumo_dam4_analysis/`, `lumo_dam6_analysis/`); not
  generated by any script in this folder. Read by
  `../code/lumo_damping_gamma2_modulation.py`. `lumo_tower_coherence_states.json`
  is also recomputable from `lumo_channels.csv` via
  `../code/recompute_lumo_coherence_states.py`.
* `audit.csv` / `audit.json` — written by `../code/lumo_burst_cache_audit.py
  --stride 10 --csv data/audit.csv`; one row per audited burst cache entry,
  including the full Sentinel-1 SAFE product name, acquisition time, subswath,
  polarisation and anchor-rule verdicts — enough to locate and download the
  exact source product from Copernicus independently. This is the committed
  record of that audit: the burst cache directory it was computed from is
  machine-local Rust-pipeline output, is not included in this repository, and
  is not required to review the analysis — only to re-run the audit from
  scratch against a live cache.
* `espoo_channels.csv` / `lumo_channels.csv` — written by
  `../code/figures_data_csv.py`; the flat, 76-column per-record CSVs the two
  channel figures (`../code/fig_espoo_channels.py`,
  `../code/fig_lumo_channels.py`) read.
* `fig_espoo_channels.json`, `fig_lumo_channels.json`,
  `fig_burst_cache_audit.json`, `lumo_damping_gamma2_modulation.json` — written
  by the matching script in `../code/` (run via the `.sh` wrapper of the same
  name in `../figures/`); the counts/stats payload behind each figure's `.md`
  report and `.png` plot, which are written to `../figures/` instead.
